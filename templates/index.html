07 / PASO A PASO

Cómo se hizo este proyecto.

El trabajo comenzó con una pregunta sobre la asistencia escolar y terminó con un modelo que se puede probar desde esta página. En cada paso se explica qué se hizo, por qué, un ejemplo y qué resultado se obtuvo. Los conteos y las métricas vienen de los archivos del proyecto.

Definir la pregunta → conocer el censo → preparar los datos → entrenar el árbol → evaluar sus respuestas → mostrarlo en Flask.

Abre los pasos para seguir el recorrido. Los fragmentos muestran las instrucciones principales; puedes consultar los archivos completos en el repositorio del proyecto.

  1. Definir qué se quiere predecir

    Qué se hizo. Se planteó una pregunta: ¿una persona de Barranquilla asistía a una institución educativa en 2018? Se eligió estudiar a personas de 5 a 24 años usando grupo de edad, sexo y parentesco.

    Por qué. Interesa conocer cómo se relacionan estas características con la asistencia escolar. Es un problema de clasificación: se aprende a elegir entre dos respuestas conocidas. El ejercicio describe patrones, no las causas de que alguien estudie o no.

    Ejemplo. En el censo, PA_ASISTENCIA = 1 significa «Sí asistía» y PA_ASISTENCIA = 2 significa «No asistía». Esas son las respuestas que el árbol debe aprender, sin recibirlas como entrada.

    Resultado. Quedaron definidos la población de estudio, las tres características de entrada y las dos clases que se van a predecir.

    Se tomó como referencia el árbol trabajado en clase. Pandas permite leer y organizar las tablas; scikit-learn permite entrenar y evaluar el árbol; Matplotlib dibuja las gráficas; Flask muestra los resultados en la web. Las librerías se encuentran en requirements.txt.

  2. Descargar los datos y separar Barranquilla

    Qué se hizo. descargar_datos.py descarga 08_Atlantico.zip del Censo 2018 del DANE y extrae la tabla PERSONAS. Cada fila representa una persona censada. El archivo se lee por partes para usar menos memoria.

    Por qué. El archivo contiene varios municipios de Atlántico, pero la pregunta del proyecto es solo sobre Barranquilla. Usar una sola fuente permite revisar de dónde viene cada dato.

    Ejemplo. Una fila pasa el filtro si tiene departamento 08 y municipio 001. La comparación usa ambos códigos:

    barranquilla = parte[
    (parte["U_DPTO"] == "08") & (parte["U_MPIO"] == "001")
]

    Resultado. De {{ '{:,}'.format(fuente.registros_atlantico).replace(',', '.') }} personas de Atlántico se conservaron {{ '{:,}'.format(limpieza.originales).replace(',', '.') }} de Barranquilla. Se guardaron en datos/poblacion_original.csv con las {{ fuente.columnas_originales|length }} columnas originales.

    Los códigos se leen como texto para conservar los ceros: 08 + 001 forman 08001. datos/fuente.json guarda los enlaces y la identificación del ZIP utilizado.

  3. Revisar y limpiar la tabla

    Qué se hizo. limpieza_datos.py selecciona {{ limpieza.columnas_limpias|length }} columnas y revisa tipos de datos, vacíos, duplicados y códigos fuera del diccionario del DANE.

    Por qué. Una fila repetida contaría dos veces al entrenar. Una respuesta vacía tampoco puede interpretarse como «No asistía». Por eso se revisan los datos antes de elegir las personas para el modelo.

    Ejemplo. Dos personas de la misma edad, sexo y parentesco siguen siendo personas distintas. Se revisan también sus identificadores de encuesta, vivienda, hogar y persona. Estas instrucciones permiten detectar vacíos y filas repetidas:

    df.info()
nulos = df.isnull().sum()
duplicados = df.duplicated().sum()
df = df.drop_duplicates().copy()

    Resultado. Se eliminaron {{ limpieza.duplicados_eliminados }} duplicados exactos y quedaron {{ '{:,}'.format(limpieza.limpios).replace(',', '.') }} personas en la base limpia. En la base general había {{ '{:,}'.format(limpieza.nulos_originales.PA_ASISTENCIA).replace(',', '.') }} respuestas vacías de asistencia; se conservaron vacías. No se rellenaron con la respuesta más frecuente ni se inventaron edades.

    Se guarda datos/poblacion_limpia.csv con todas las edades. resumen_limpieza.json conserva los conteos de la limpieza y resumen_poblacion.csv contiene los seis perfiles más frecuentes, agrupados para mostrarlos en la página.

    Qué se hizo. arbol_decision.py selecciona personas de 5 a 24 años con respuesta 1 o 2, sexo y parentesco válidos e identificación del hogar disponible.

    Por qué. Para aprender y comprobar una predicción hace falta conocer la respuesta real. «No informa» y «No aplica» no son respuestas negativas. La identificación del hogar permite mantener juntas a las personas que viven en él.

    Ejemplo. Los códigos de edad 2, 3, 4 y 5 corresponden a 5–9, 10–14, 15–19 y 20–24 años. El filtro de asistencia conserva solo los códigos 1 y 2:

    datos = df[df["P_EDADR"].isin([2, 3, 4, 5])].copy()
datos = datos[datos["PA_ASISTENCIA"].isin([1, 2])]

  5. Preparar las entradas y la respuesta

    Qué se hizo. Se separaron las características en X y la respuesta real en y. El parentesco se convirtió en cinco columnas de 0 y 1, una por opción.

    Por qué. Los grupos de edad tienen un orden, pero los parentescos no: «otro pariente» no es mayor ni menor que «hijo». Las columnas de 0 y 1 permiten preguntar si la persona pertenece a una categoría sin imponer ese orden.

    Qué significa cada variable y cómo se utiliza
    VariableTipoUso
    P_EDADROrdinal: grupos ordenadosEntrada; códigos 2 a 5, no edad exacta
    P_SEXONominal binaria: dos categorías sin ordenEntrada; 1 hombre, 2 mujer
    P_PARENTESCORNominal: categorías sin ordenEntrada; cinco columnas de 0 y 1
    PA_ASISTENCIABinaria: Sí o No en la selecciónRespuesta que se aprende; nunca es entrada

    Ejemplo. Para representar «hijo o hijastro», las cinco columnas de parentesco quedan [0, 0, 1, 0, 0]. Es un ejemplo de codificación, no una persona añadida a los datos.

    entradas = datos[["P_EDADR", "P_SEXO"]].copy()
for codigo in [1, 2, 3, 4, 5]:
    entradas["P_PARENTESCOR_" + str(codigo)] = (
        datos["P_PARENTESCOR"] == codigo
    ).astype(int)
X = entradas.to_numpy()
y = datos["PA_ASISTENCIA"].to_numpy()

    Resultado. El modelo recibe siete columnas numéricas que representan tres características: una de edad, una de sexo y cinco de parentesco. La asistencia, los identificadores, el nivel educativo y la actividad laboral no se incluyen entre las entradas.

  6. Separar entrenamiento y prueba por hogares

    Qué se hizo. Se unieron los códigos de encuesta, vivienda y hogar. Se repartió al azar el 80% de los hogares para entrenamiento y el 20% para prueba.

    Por qué. Evaluar con las mismas personas usadas al aprender daría una impresión demasiado favorable. Además, quienes viven juntos pueden tener características parecidas; mantener cada hogar en un solo grupo reduce ese problema.

    Ejemplo. Si un hogar tiene tres personas seleccionadas, las tres quedan en entrenamiento o las tres en prueba. No se reparte a sus miembros por separado.

    datos["hogar"] = (
    datos["COD_ENCUESTAS"] + "-" + datos["U_VIVIENDA"]
    + "-" + datos["P_NROHOG"]
)
hogares_entrenamiento, hogares_prueba = train_test_split(
    datos["hogar"].unique(), test_size=0.20, random_state=42
)

    Después se seleccionan las personas de cada grupo para formar X_train, y_train, X_test y y_test. Todos los miembros de un hogar quedan juntos para evitar evaluar con familiares de las personas usadas al entrenar.

    Resultado. Quedaron {{ '{:,}'.format(resultados.entrenamiento).replace(',', '.') }} personas de {{ '{:,}'.format(resultados.hogares_entrenamiento).replace(',', '.') }} hogares para entrenar y {{ '{:,}'.format(resultados.prueba).replace(',', '.') }} personas de {{ '{:,}'.format(resultados.hogares_prueba).replace(',', '.') }} hogares para probar. Ningún hogar aparece en ambos conjuntos.

    Como se sortean hogares de distinto tamaño, el porcentaje de personas no tiene que ser exactamente 80/20. Se comprueba que ambos grupos tengan respuestas «Sí» y «No». El valor 42 permite repetir el sorteo con los mismos datos.

  7. Crear el árbol y entrenarlo con fit()

    Qué se hizo. Se creó un DecisionTreeClassifier pequeño y se entrenó con las características y respuestas del grupo de entrenamiento.

    Por qué. Un árbol construye preguntas del tipo «si se cumple esto, seguir por aquí». En cada división busca separar mejor las clases. Se limita su tamaño para que las reglas se puedan leer y explicar.

    Ejemplo. Puede preguntar si el código de edad es menor o igual que 3,5. Esa pregunta separa los grupos de 5–14 años de los de 15–24; no significa que alguien tenga 3,5 años.

    modelo = tree.DecisionTreeClassifier(
    max_depth=3, min_samples_leaf=100, random_state=42
)
modelo.fit(X_train, y_train)

    DecisionTreeClassifier crea el árbol. max_depth=3 limita la cantidad de niveles de preguntas y min_samples_leaf=100 exige al menos 100 personas de entrenamiento en cada hoja.

    Resultado. .fit() produjo un árbol con {{ resultados.profundidad }} niveles de preguntas y {{ resultados.hojas }} hojas. Cada camino hasta una hoja forma una regla; la clase más frecuente de esa hoja es la predicción.

  8. Predecir y contar los aciertos

    Qué se hizo. Se pidieron predicciones para las personas de prueba y se compararon con sus respuestas reales. También se calculó un punto de comparación: responder siempre la clase más común del entrenamiento.

    Por qué. Un porcentaje de aciertos necesita contexto. Si muchas personas respondieron lo mismo, repetir esa respuesta ya produce aciertos. El árbol debe aportar algo frente a esa regla sencilla.

    Ejemplo. La matriz se lee por filas reales y columnas predichas, en el orden Sí, No:

    • {{ '{:,}'.format(resultados.matriz[0][0]).replace(',', '.') }} personas respondieron «Sí» y el árbol predijo «Sí»: aciertos.
    • {{ '{:,}'.format(resultados.matriz[0][1]).replace(',', '.') }} respondieron «Sí» y el árbol predijo «No»: errores.
    • {{ '{:,}'.format(resultados.matriz[1][0]).replace(',', '.') }} respondieron «No» y el árbol predijo «Sí»: errores.
    • {{ '{:,}'.format(resultados.matriz[1][1]).replace(',', '.') }} respondieron «No» y el árbol predijo «No»: aciertos.
    predicciones = modelo.predict(X_test)
exactitud = accuracy_score(y_test, predicciones)
matriz = confusion_matrix(y_test, predicciones, labels=[1, 2])

    .predict() recorre el árbol con las características de las personas de prueba, sin recibir sus respuestas reales. Después se comparan las predicciones con y_test.

    Resultado. accuracy_score() divide {{ '{:,}'.format(resultados.aciertos).replace(',', '.') }} aciertos entre {{ '{:,}'.format(resultados.prueba).replace(',', '.') }} personas: {{ '%.2f'|format(resultados.exactitud * 100) }}%. Responder siempre «Sí asistía» obtiene {{ '%.2f'|format(resultados.exactitud_base * 100) }}%. El árbol mejora {{ '%.2f'|format((resultados.exactitud - resultados.exactitud_base) * 100) }} puntos porcentuales frente a esa respuesta fija.

    La precisión indica qué parte de las predicciones de una clase acertó. La recuperación o recall indica qué parte de las personas reales de esa clase se encontró. F1 combina ambas: no será alto si una de ellas es baja. classification_report() calcula estas medidas.

  9. Dibujar el árbol y las gráficas

    Qué se hizo. arbol_decision.py dibuja el árbol con tree.plot_tree() y la matriz con ConfusionMatrixDisplay. graficas.py prepara las gráficas de población.

    Por qué. Las imágenes permiten revisar las preguntas aprendidas, los errores y las diferencias entre grupos sin tener que leer todas las filas del censo.

    Ejemplo. Para leer una caja del árbol:

    • La primera línea contiene la pregunta. Si se cumple, se sigue la rama izquierda; si no, la derecha.
    • samples cuenta las personas de entrenamiento que llegaron a esa caja.
    • value muestra las cantidades en el orden [Sí asistía, No asistía].
    • class indica la respuesta más frecuente. Al llegar a una hoja, esa es la predicción.
    • En esta imagen, naranja representa «Sí asistía» y azul, «No asistía». Un color más intenso indica que una clase predomina más en esa caja.

    graficas.py cuenta las personas por edad, sexo y asistencia y guarda las cuatro gráficas en imagenes/graficas.png. Este archivo no vuelve a entrenar el modelo.

    Resultado. Se guardan arbol.png, matriz_confusion.png y graficas.png en imagenes/. Las gráficas generales de edad y sexo usan toda la población; las de asistencia se centran en 5–24 años. Los grupos de la gráfica general de edad tienen distinta amplitud.

  10. Guardar el modelo y sus resultados

    Qué se hizo. pickle.dump() guarda el árbol entrenado y las opciones del formulario en modelo.pkl. Las métricas y las predicciones se guardan en archivos separados.

    Por qué. La página necesita reutilizar el modelo y mostrar los resultados sin entrenarlo cada vez que alguien la abre. Guardar las predicciones también permite comprobar después cómo se calculó la evaluación.

    Ejemplo. pickle.load() recupera el modelo guardado. El archivo contiene el árbol que aprendió las reglas y las etiquetas que usa el formulario.

    datos/resultados.json conserva las métricas. datos/datos_modelo.csv indica qué personas quedaron en entrenamiento y prueba. datos/predicciones_prueba.csv guarda las respuestas reales y las predichas para compararlas.

    Resultado. El modelo, las métricas y los CSV quedan disponibles para la web y las comprobaciones. Se guarda el mismo árbol que se evaluó; no se vuelve a entrenar con las personas reservadas para prueba.

  11. Conectar el formulario con Flask

    Qué se hizo. app.py carga el modelo, los resúmenes y los resultados. templates/index.html organiza las secciones y el formulario. static/style.css define los colores, los tamaños y la adaptación a celulares.

    Por qué. Flask permite que quien visita la página elija las características y reciba una respuesta del modelo sin escribir instrucciones de Python.

    Ejemplo. Si se selecciona el grupo de 10–14 años, hombre e hijo o hijastro, la entrada se representa como [3, 1, 0, 0, 1, 0, 0]. Es un perfil ilustrativo del formulario; la respuesta se obtiene al consultar el modelo.

    Al abrir la página, Flask recibe una petición GET y muestra el contenido. Al pulsar «Predecir», recibe una petición POST con edad, sexo y parentesco. Revisa que las opciones sean válidas y prepara las columnas en el mismo orden que durante el entrenamiento.

    nuevos_valores = [entrada]
predicciones = modelo.predict(nuevos_valores)
codigo_prediccion = int(predicciones[0])
prediccion = guardado["clases"][codigo_prediccion]

    Resultado. El código 1 o 2 se convierte en «Sí asistía» o «No asistía». Cada envío consulta el modelo guardado; no lo entrena ni guarda los datos del visitante. La predicción corresponde a patrones de 2018, no verifica la situación actual de una persona.

  12. Comprobar que todo funcione

    Qué se hizo. verificar_proyecto.py revisa los conteos, los códigos de edad, las dos respuestas y que ningún hogar esté en ambos grupos. Vuelve a calcular las predicciones y comprueba que coincidan con las guardadas.

    Por qué. Que el programa termine no basta: los archivos deben coincidir entre sí y el formulario debe consultar correctamente el modelo.

    Ejemplo. Si se envía un código de edad que no pertenece a 5–24 años, el formulario debe rechazarlo. Si un hogar apareciera en entrenamiento y prueba, la comprobación tendría que fallar.

    También prueba las 40 combinaciones del formulario: 4 grupos de edad × 2 sexos × 5 parentescos. Revisa que se rechacen opciones inválidas y que se puedan cargar las imágenes y descargar el CSV.

    Resultado. Las comprobaciones del proyecto pasaron. También se probó la web en una copia sin el ZIP ni los CSV grandes: cargó con el modelo y los resúmenes guardados. La integridad del ejemplo original de clase solo se comprueba si ese archivo está presente.

    Para repetir todo el análisis, se ejecutan estos archivos en orden, después de instalar las librerías:

  13. Preparar la publicación en internet

    Qué se hizo. Se subió el proyecto a GitHub y se preparó render.yaml para ejecutar Flask en un servidor. .gitignore excluye el entorno de Python, las cachés, el ZIP y los CSV grandes que se pueden volver a generar.

    Por qué. Guardar código en GitHub no ejecuta una aplicación Flask. Hace falta un servidor que reciba las visitas y las solicitudes del formulario.

    Ejemplo. Al abrir el enlace público, el navegador solicita la página al servidor. Al pulsar «Predecir», el servidor consulta modelo.pkl y devuelve el resultado.

    render.yaml configura un servicio Flask en Render. El servidor instala las librerías y usa Gunicorn para atender las visitas. La web lee el modelo entrenado, las imágenes, los resultados y los conteos agrupados que sí están en el repositorio.

    Resultado. El proyecto queda preparado para compartir la web cuando el servicio termine de publicarse. Los visitantes no necesitan instalar Python ni tener los archivos locales. Las actualizaciones de código se activan desde Render con Manual Deploy → Deploy latest commit.
