04 / EL MODELO DE CLASIFICACIÓN

Preguntas sencillas, dos respuestas posibles.

El árbol aprende relaciones entre grupo de edad, sexo y parentesco. La etiqueta es la respuesta censal PA_ASISTENCIA; nunca se utiliza como entrada.

Clase 1Sí asistía
Clase 2No asistía

El parentesco se representa con columnas de 0 y 1, una por categoría. Así se evita interpretarlo como una escala numérica. No se usan actividad laboral, nivel educativo o alfabetismo, para reducir el riesgo de revelar indirectamente la respuesta.

“Grupo de edad ≤ 3,5” separa los códigos 2 y 3 (5–14 años) de 4 y 5 (15–24 años). Las preguntas del árbol comparan códigos de grupos, no edades exactas.

Qué podemos concluir

  • El árbol mejora frente a responder siempre la clase más común, aunque sigue cometiendo errores.
  • Las tres características disponibles no explican por completo la asistencia educativa. Una persona puede diferir del patrón de su grupo.
  • El estudio usa el censo de 2018 y personas de 5–24 años con respuestas completas. No demuestra causas ni está validado para otros años, edades o ciudades.
  • “No informa” y “No aplica” no se interpretan como “No asistía”. La ausencia de respuestas puede afectar la representatividad del modelo.
  • La separación por hogar reduce la similitud entre entrenamiento y prueba, pero no elimina toda relación entre vecinos o zonas.

07 / PASO A PASO

Cómo se hizo este proyecto.

Esta guía sigue el orden del trabajo, desde descargar el censo hasta mostrar una predicción en la página. Abre cada paso para ver la explicación. Los fragmentos de código muestran las instrucciones principales; los archivos completos están en el repositorio del proyecto.

  1. Definir qué se quiere predecir

    La pregunta fue: ¿una persona de Barranquilla asistía a una institución educativa en 2018? El censo ya contiene la respuesta en PA_ASISTENCIA: 1 significa «Sí» y 2 significa «No». Se eligieron personas de 5 a 24 años.

    Se tomó como referencia el árbol trabajado en clase. Pandas permite leer y organizar las tablas; scikit-learn permite entrenar y evaluar el árbol; Matplotlib dibuja las gráficas; Flask muestra los resultados en la web. Las librerías se encuentran en requirements.txt.

  2. Descargar los datos y separar Barranquilla

    descargar_datos.py descarga 08_Atlantico.zip del Censo 2018 del DANE, abre el archivo PERSONAS y lo lee por partes para usar menos memoria.

    barranquilla = parte[
    (parte["U_DPTO"] == "08") & (parte["U_MPIO"] == "001")
]

    El departamento 08 y el municipio 001 forman el código 08001. Los códigos se leen como texto para conservar los ceros. El resultado se guarda en datos/poblacion_original.csv, con {{ '{:,}'.format(limpieza.originales).replace(',', '.') }} personas y las {{ fuente.columnas_originales|length }} columnas originales.

  3. Revisar y limpiar la tabla

    limpieza_datos.py selecciona las columnas necesarias y revisa tipos de datos, vacíos y duplicados.

    df.info()
nulos = df.isnull().sum()
duplicados = df.duplicated().sum()
df = df.drop_duplicates().copy()

    Se usan también los códigos de cada persona para revisar duplicados: dos personas con las mismas características no son una sola. Los códigos demográficos se comparan con el diccionario del DANE. Una respuesta vacía se conserva vacía, porque no significa «No asistía».

    Se guarda datos/poblacion_limpia.csv con todas las edades. resumen_limpieza.json conserva los conteos de la limpieza y resumen_poblacion.csv contiene los seis perfiles más frecuentes, agrupados para mostrarlos en la página.

  4. Seleccionar las personas para el árbol

    arbol_decision.py lee el CSV limpio y conserva los códigos de edad 2, 3, 4 y 5, que corresponden a 5–9, 10–14, 15–19 y 20–24 años.

    datos = df[df["P_EDADR"].isin([2, 3, 4, 5])].copy()
datos = datos[datos["PA_ASISTENCIA"].isin([1, 2])]

    También se revisan sexo, parentesco e identificación del hogar. «No aplica», «No informa» y los valores faltantes se excluyen del modelo cuando impiden usar una fila. Permanecen {{ '{:,}'.format(resultados.personas_modelo).replace(',', '.') }} personas utilizables; el programa comprueba que sean más de 10.000 y que los datos correspondan a Barranquilla.

  5. Preparar las entradas y la respuesta

    Las entradas son grupo de edad (P_EDADR), sexo (P_SEXO) y parentesco (P_PARENTESCOR). La respuesta que queremos aprender es PA_ASISTENCIA; no se incluye entre las entradas.

    entradas = datos[["P_EDADR", "P_SEXO"]].copy()
for codigo in [1, 2, 3, 4, 5]:
    entradas["P_PARENTESCOR_" + str(codigo)] = (
        datos["P_PARENTESCOR"] == codigo
    ).astype(int)
X = entradas.to_numpy()
y = datos["PA_ASISTENCIA"].to_numpy()

    El parentesco se convierte en cinco columnas de 0 y 1. Para un hijo o hijastro, por ejemplo, quedan [0, 0, 1, 0, 0]. Así el árbol no interpreta que un parentesco sea «mayor» que otro. X contiene las características y y, las respuestas reales.

  6. Separar entrenamiento y prueba por hogares

    Se unen los códigos de encuesta, vivienda y hogar para identificar a quienes viven juntos. Se reparte el 80% de los hogares para aprender y el 20% para probar.

    datos["hogar"] = (
    datos["COD_ENCUESTAS"] + "-" + datos["U_VIVIENDA"]
    + "-" + datos["P_NROHOG"]
)
hogares_entrenamiento, hogares_prueba = train_test_split(
    datos["hogar"].unique(), test_size=0.20, random_state=42
)

    Después se seleccionan las personas de cada grupo para formar X_train, y_train, X_test y y_test. Todos los miembros de un hogar quedan juntos para evitar evaluar con familiares de las personas usadas al entrenar.

    Quedaron {{ '{:,}'.format(resultados.entrenamiento).replace(',', '.') }} personas de entrenamiento y {{ '{:,}'.format(resultados.prueba).replace(',', '.') }} de prueba. Se comprueba que ambos grupos tengan respuestas «Sí» y «No». El valor 42 fija el sorteo para poder repetir la separación con los mismos datos.

  7. Crear el árbol y entrenarlo con fit() 
    modelo = tree.DecisionTreeClassifier(
    max_depth=3, min_samples_leaf=100, random_state=42
)
modelo.fit(X_train, y_train)

    DecisionTreeClassifier crea el árbol. max_depth=3 limita la cantidad de niveles de preguntas y min_samples_leaf=100 exige al menos 100 personas de entrenamiento en cada hoja.

    .fit() busca preguntas que ayuden a separar las respuestas «Sí» y «No» usando solo el grupo de entrenamiento. El árbol resultante tiene {{ resultados.profundidad }} niveles de preguntas y {{ resultados.hojas }} hojas.

  8. Predecir y contar los aciertos 
    predicciones = modelo.predict(X_test)
exactitud = accuracy_score(y_test, predicciones)
matriz = confusion_matrix(y_test, predicciones, labels=[1, 2])

    .predict() recorre el árbol con las características de las personas de prueba, sin recibir sus respuestas reales. Después se comparan las predicciones con y_test.

    accuracy_score() divide los aciertos entre el total de personas de prueba: {{ '{:,}'.format(resultados.aciertos).replace(',', '.') }} / {{ '{:,}'.format(resultados.prueba).replace(',', '.') }} = {{ '%.2f'|format(resultados.exactitud * 100) }}%. La matriz muestra qué respuestas se acertaron y cuáles se confundieron.

    classification_report() calcula los resultados por clase. También se compara el árbol con responder siempre la opción más frecuente del entrenamiento, que obtiene {{ '%.2f'|format(resultados.exactitud_base * 100) }}% en la prueba. Esto ayuda a interpretar si el árbol aporta una mejora.

  9. Dibujar el árbol y las gráficas

    arbol_decision.py usa tree.plot_tree() para dibujar el árbol y ConfusionMatrixDisplay para la matriz. Guarda las imágenes como imagenes/arbol.png y imagenes/matriz_confusion.png.

    Para leer el árbol, se empieza arriba: si se cumple la pregunta, se sigue la rama izquierda; si no, la derecha. La hoja final indica «Sí asistía» o «No asistía».

    graficas.py cuenta las personas por edad, sexo y asistencia y guarda las cuatro gráficas en imagenes/graficas.png. Este archivo no vuelve a entrenar el modelo.

  10. Guardar el modelo y sus resultados

    pickle.dump() guarda el árbol entrenado y las opciones del formulario en modelo.pkl. Así la página puede cargarlo sin repetir el entrenamiento.

    datos/resultados.json conserva las métricas. datos/datos_modelo.csv indica qué personas quedaron en entrenamiento y prueba. datos/predicciones_prueba.csv guarda las respuestas reales y las predichas para compararlas.

    Se guarda el mismo árbol que se evaluó: no se vuelve a entrenar con las personas reservadas para prueba.

  11. Conectar el formulario con Flask

    app.py carga el modelo, los resúmenes y los resultados. templates/index.html organiza las secciones y el formulario. static/style.css define los colores, los tamaños y la adaptación a celulares.

    Al abrir la página, Flask recibe una petición GET y muestra el contenido. Al pulsar «Predecir», recibe una petición POST con edad, sexo y parentesco. Revisa que las opciones sean válidas y prepara las columnas en el mismo orden que durante el entrenamiento.

    nuevos_valores = [entrada]
predicciones = modelo.predict(nuevos_valores)
codigo_prediccion = int(predicciones[0])
prediccion = guardado["clases"][codigo_prediccion]

    El código 1 o 2 se convierte en un texto que se muestra en la página. Cada envío usa el modelo guardado; no lo entrena ni guarda los datos del visitante. La predicción corresponde a patrones de 2018.

  12. Comprobar que todo funcione

    verificar_proyecto.py revisa los conteos, los códigos de edad, las dos respuestas y que ningún hogar esté en ambos grupos. Vuelve a calcular las predicciones y comprueba que coincidan con las guardadas.

    También prueba las 40 combinaciones del formulario: 4 grupos de edad × 2 sexos × 5 parentescos. Revisa que se rechacen opciones inválidas y que se puedan cargar las imágenes y descargar el CSV.

    Para repetir todo el análisis, se ejecutan estos archivos en orden, después de instalar las librerías:

    python descargar_datos.py
python limpieza_datos.py
python arbol_decision.py
python graficas.py
python verificar_proyecto.py
python app.py

    En el entorno local preparado para este proyecto, se usa .\.venv\Scripts\python.exe en lugar de python. Descargar y entrenar se hace al preparar o actualizar el análisis; no en cada visita.

  13. Preparar la publicación en internet

    GitHub guarda el código del proyecto. .gitignore excluye el entorno de Python, las cachés, el ZIP y los CSV grandes que se pueden volver a generar.

    render.yaml configura un servicio Flask en Render. El servidor instala las librerías y usa Gunicorn para atender las visitas. La web lee el modelo entrenado, las imágenes, los resultados y los conteos agrupados que sí están en el repositorio.

    Cuando el servicio termina de publicarse, se puede compartir su enlace sin que los visitantes instalen el proyecto. Las actualizaciones de código se activan desde Render con Manual Deploy → Deploy latest commit.

Para explicar el proyecto: primero se obtuvieron y limpiaron los datos, después se separaron hogares para entrenar y evaluar el árbol, y al final se conectó el modelo con el formulario de Flask.
